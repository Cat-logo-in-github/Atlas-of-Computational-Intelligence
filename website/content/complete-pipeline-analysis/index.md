# Complete Pipeline Analysis

This document brings together the four major components of the cell-tracking pipeline:

1. [Image Preprocessing](../image-preprocessing/knowledge.md)
2. [Temporal U-Net](../temporal-unet//knowledge.md)
3. [Simple Node Transformer](../simple-node-transformer/knowledge.md)
4. [Graph Construction](../graph-construction/knowledge.md)

The central idea is that the pipeline does **not** directly predict complete cell tracks.

Instead, it progressively transforms the microscopy image into a tracking graph:

```text
Microscopy image
      │
      ▼
Image preprocessing
      │
      ▼
Temporal U-Net
      │
      ├───────────────┐
      │               │
      ▼               ▼
Detection logits   U-Net features
      │               │
      ▼               │
Cell detections ◄─────┘
      │
      ▼
Node features
      │
      ▼
Simple Node Transformer
      │
      ▼
Temporal edge scores
      │
      ▼
Edge filtering / constraints
      │
      ▼
Tracking graph
      │
      ▼
Optional ILP optimization
      │
      ▼
.geff output
```

The most useful mental model is:

> **The U-Net finds candidate cells, the node transformer decides which cells are temporally related, and graph processing turns those decisions into complete tracks.**

# 2. Stage 1 — Image Preprocessing

The first stage converts the raw microscopy data into the representation expected by the neural network.

The main operations are:

```text
Zarr image
   │
   ├── metadata parsing
   │
   ├── quantile normalization
   │
   └── spatial downsampling
   │
   ▼
model-ready image window
```

See [Image Preprocessing](../image-preprocessing/knowledge.md) for the detailed explanation of normalization, anisotropic voxel sizes, downsampling, TTA, and coordinate systems.

## 2.1 Dataset metadata

The dataset loader reads both the image and relevant metadata.

An important piece of metadata is the physical voxel scale:

```python
DEFAULT_SCALE = (1.625, 0.40625, 0.40625)
```

which represents:

```text
(Z, Y, X)

Z = 1.625 µm
Y = 0.40625 µm
X = 0.40625 µm
```

This means the microscopy volume is anisotropic.

One Z voxel represents substantially more physical distance than one Y or X voxel.

This distinction matters whenever the pipeline works with physical distances.

---

# 3. Quantile Normalization

The raw image intensities are normalized before being passed to the model.

The general transformation is:

```text
normalized =
    (image - q_low)
    ----------------
    (q_high - q_low + ε)
```

followed by clipping.

The inference configuration uses dataset statistics corresponding approximately to:

```text
0.1th percentile
       │
       ▼
linear scaling
       │
       ▼
99.9th percentile
       │
       ▼
clipping
```

The statistics are stored in:

```text
image_statistics.quantiles
```

and the relevant quantiles are:

```text
0.001
0.999
```

This is important because the neural network was trained under a particular intensity distribution.

Changing the normalization convention can therefore change the distribution seen by the model.

---

# 4. Spatial Downsampling

The model configuration uses:

```python
downsample = (1, 4, 4)
```

This means:

```text
Z → 1×
Y → 4×
X → 4×
```

In other words:

```text
Z:
keep the original sampling

Y:
reduce the spatial resolution by 4

X:
reduce the spatial resolution by 4
```

This substantially reduces the computational cost of processing large 3D volumes.

The important consequence is that detections initially exist in the **downsampled model coordinate system**.

Later, those coordinates are converted back to the original image coordinate system.

# 5. Stage 2 — Temporal U-Net

The preprocessed image is passed through `TemporalUNet3D`.

See [Temporal U-Net](../temporal-unet/knowledge.md) for the detailed architecture and detection process.

The supplied configuration is approximately:

```text
input channels:       1
U-Net output:         32
U-Net layers:         [32, 64, 128]
downsample:           [1, 4, 4]
window size:          2
pool scale:           5.0 µm
```

The model receives a temporal window:

```text
(W, Z, Y, X)
```

For the supplied model:

```text
W = 2
```

so inference processes consecutive pairs:

```text
(frame 0, frame 1)
(frame 1, frame 2)
(frame 2, frame 3)
...
```

The U-Net produces two important outputs:

```python
unet_out, det_logits = model.encode(imgs)
```

These outputs serve different purposes.

# 6. Dense Features vs. Detection Logits

The U-Net produces dense spatial representations.

Conceptually:

```text
Input image
     │
     ▼
Temporal U-Net
     │
     ├───────────────┐
     ▼               ▼
U-Net features   detection logits
```

The detection logits answer:

> Where does the network think a cell center may exist?

The U-Net feature volume answers:

> What does the image look like around each spatial location?

This distinction is fundamental.

The U-Net does **not** directly produce graph nodes.

Instead:

```text
dense detection field
        │
        ▼
local maxima
        │
        ▼
discrete cell detections
```

The dense feature volume is then sampled at those detected locations.

---

# 7. Detection

For every frame, the detector produces a logit volume:

```text
(Z, Y, X)
```

The logits can be converted to probabilities using:

```python
torch.sigmoid(logits)
```

A candidate cell is identified when:

1. it is a local maximum;
2. its detection score exceeds the configured threshold.

The local maximum operation uses 3D max pooling:

```python
pooled = F.max_pool3d(...)
is_peak = (
    (logits == pooled)
    & (torch.sigmoid(logits) > threshold)
)
```

The result is a list of cell coordinates:

```text
(t, z, y, x)
```

For example:

```text
t   z   y    x
0   4   31   82
0   5   74   51
0   7   19   93
```

These detections become the nodes used by the downstream tracking pipeline.

---

# 8. Detection Threshold

The inference CLI uses a relatively high default detection threshold:

```python
--det-threshold 0.99
```

This should not necessarily be interpreted as:

> "99% probability that a cell exists."

Instead, it is better understood as a precision/recall control.

Lower threshold:

```text
lower threshold
      │
      ▼
more detections
      │
      ▼
higher recall
      │
      ▼
potentially more false positives
```

Higher threshold:

```text
higher threshold
      │
      ▼
fewer detections
      │
      ▼
higher precision
      │
      ▼
potentially more missed cells
```

This stage is independent from temporal linking.

A cell that is never detected cannot be recovered by the transformer.

---

# 9. Test-Time Augmentation

The inference pipeline can use test-time augmentation (TTA).

The idea is to run the detector on several orientations of the same image.

The current configuration uses:

```text
original
flip X
flip Y
flip X + Y
```

For each transformed image:

```text
input
  │
  ▼
flip
  │
  ▼
Temporal U-Net
  │
  ▼
detection logits
  │
  ▼
flip logits back
```

The predictions are then averaged.

Conceptually:

```text
                 Original
                    │
          ┌─────────┼─────────┐
          │         │         │
          ▼         ▼         ▼
        flip X    flip Y    flip XY
          │         │         │
          ▼         ▼         ▼
        U-Net     U-Net     U-Net
          │         │         │
          ▼         ▼         ▼
      undo flip  undo flip  undo flip
          │         │         │
          └─────────┼─────────┘
                    │
                    ▼
             average logits
                    │
                    ▼
             final detection
```

Importantly, the flips are applied to the **input image**, not to already-thresholded detections.

The transformed logits are returned to the original coordinate orientation before averaging.

# 10. Stage 3 — From Cells to Node Features

Once cell centers have been detected, each node needs a representation that the transformer can use.

Each detected cell has:

```text
(t, z, y, x)
```

Two complementary sources of information are attached to it:

```text
                detected cell
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
     U-Net feature          position
        32-D                 (t,z,y,x)
          │                     │
          │                     ▼
          │              positional encoding
          │                     │
          │                     ▼
          │                  32-D
          │                     │
          └──────────┬──────────┘
                     ▼
                concatenation
                     │
                     ▼
                64-D node
```

The two components have different meanings.

### U-Net feature

```text
"What does this cell look like?"
```

### Positional feature

```text
"Where is this cell?"
```

The final representation combines both.

---

# 11. Positional Encoding

The coordinates:

```text
(t, z, y, x)
```

are converted into a 32-dimensional positional representation.

See [Simple Node Transformer](../simple-node-transformer/knowledge.md#-4.-Positional-encoding) for the detailed derivation.

The transformation is:

```text
(t,z,y,x)
     │
     ▼
normalize by image dimensions
     │
     ▼
4 frequencies
     │
     ▼
sin + cos
     │
     ▼
8 values per coordinate
     │
     ▼
32-D positional feature
```

Each coordinate contributes:

```text
4 frequencies × 2 functions
=
8 values
```

The frequencies are:

```text
[1, 2, 4, 8]
```

and each frequency produces:

```text
sin(angle)
cos(angle)
```

Therefore:

```text
t → 8 values
z → 8 values
y → 8 values
x → 8 values

4 × 8 = 32
```

---

# 12. What Positional Encoding Does Not Represent

The positional encoding does **not** encode cell size.

For example:

```text
Cell A:
center = (t,z,y,x)
size   = small

Cell B:
center = (t,z,y,x)
size   = large
```

Both cells would have the same positional representation because their coordinates are identical.

The positional feature describes:

```text
where the cell is
```

It does not describe:

```text
cell radius
cell diameter
cell volume
cell morphology
```

Appearance and local image context are instead represented through the U-Net feature.

This gives the transformer two complementary information sources:

```text
U-Net feature
    │
    └── learned appearance/context

Positional encoding
    │
    └── deterministic spatial/temporal position
```

# 13. The 64-D Node Representation

Each detected cell receives:

```text
32-D U-Net feature
+
32-D positional feature
```

giving:

```text
64-D node feature
```

Conceptually:

```text
0 ───────────────────────── 31
│     U-Net feature        │
│     learned              │
└──────────────────────────┘

32 ──────────────────────── 63
│   positional feature     │
│   deterministic          │
└──────────────────────────┘
```

Therefore:

```text
64-D node
=
32-D learned image representation
+
32-D positional representation
```

The 64 dimensions are not 64 physical measurements.

They are a learned feature representation used by the transformer.

# 14. Stage 4 — Simple Node Transformer

The transformer operates on the detected nodes.

See [Simple Node Transformer](../simple-node-transformer/knowledge.md) for the detailed explanation of the node representation, attention mechanism, and edge prediction.

For two consecutive frames:

```text
Frame t                    Frame t+1

   A ──────────────────────── ? ── D
   B ──────────────────────── ? ── E
   C ──────────────────────── ? ── F
```

Each node contains:

```text
[U-Net feature | positional feature]
```

The transformer uses these representations to evaluate temporal compatibility.

The output is a matrix:

```text
(n_src, n_tgt)
```

where:

```text
row    = source node
column = target node
value  = compatibility score
```

For example:

```text
             target
             D      E      F

source A    2.1   -1.2    0.4
source B   -0.8    3.7    0.1
source C    0.2   -0.4    4.2
```

These values are still **logits**.

They are not yet final graph edges.

---

# 15. From Edge Logits to Probabilities

The configured edge activation is:

```python
edge_activation = "softmax"
```

Therefore, the raw compatibility scores are normalized using softmax.

Conceptually:

```text
edge logits
    │
    ▼
 softmax
    │
    ▼
relative edge probabilities
    │
    ▼
thresholding
```

Softmax and sigmoid represent different modeling assumptions.

### Softmax

```text
"Which target is this source most compatible with?"
```

### Sigmoid

```text
"How plausible is this source-target pair independently?"
```

The current configuration uses softmax.

---

# 16. Sliding Temporal Windows

The entire video is not necessarily processed as one giant tensor.

Instead, the inference code uses temporal windows.

For:

```text
window_size = 2
```

the sequence becomes:

```text
[0,1]
   [1,2]
      [2,3]
         [3,4]
```

The window allows the U-Net to process temporal context while the final tracking graph remains global.

The prediction code maintains registries such as:

```python
seen_frames
seen_pairs
coord_offset
```

These prevent duplicate processing when windows overlap.

The result is a single global collection of:

```text
nodes
+
temporal edges
```

even though the neural network was evaluated on smaller temporal windows.

# 17. Coordinate Systems

One of the easiest places to make mistakes is confusing the different coordinate systems.

There are three important representations.

## 17.1 Original image coordinates

The source dataset uses:

```text
(T, Z, Y, X)
```

These coordinates correspond to the original Zarr image.

---

## 17.2 Downsampled model coordinates

After:

```python
downsample = (1, 4, 4)
```

the model operates on:

```text
Z → original resolution
Y → 1/4 resolution
X → 1/4 resolution
```

Detections generated directly from the model therefore initially exist in this reduced coordinate system.

---

## 17.3 Output coordinates

At the end of inference, the spatial coordinates are rescaled:

```python
coords[:, 1:] *= ds_arr
```

This converts:

```text
model coordinates
```

back into:

```text
original image coordinates
```

Therefore the final `.geff` graph uses coordinates corresponding to the original image coordinate system.

# 18. Physical Distance vs. Voxel Distance

The image is anisotropic:

```text
Z = 1.625 µm
Y = 0.40625 µm
X = 0.40625 µm
```

Therefore:

```text
1 Z voxel
```

is not physically equivalent to:

```text
1 X voxel
```

This matters for detection suppression and edge distances.

For example, a physical distance must account for the voxel scale:

```text
physical displacement
=
voxel displacement
×
voxel size
```

The pipeline therefore keeps track of the physical scale when operations require physical geometry.

This is why a pooling distance such as:

```python
pool_kernel_um = 5.0
```

should not simply be interpreted as:

```text
5 voxels in every direction
```

Instead, the physical distance is converted into an appropriate per-axis voxel extent.

# 19. Optional Isotropic Resampling

The repository also provides utilities for explicitly converting anisotropic volumes into isotropic voxel space.

For example:

```python
resample_image_to_isotropic(...)
```

can transform:

```text
Z = 1.625 µm
Y = 0.40625 µm
X = 0.40625 µm
```

into approximately:

```text
Z ≈ Y ≈ X
```

Corresponding coordinate utilities include:

```python
rescale_coords_to_isotropic(...)
rescale_coords_from_isotropic(...)
```

However, this should not be confused with the normal Temporal U-Net prediction path.

The default prediction pipeline can operate directly on the native anisotropic data while explicitly accounting for physical scale.

# 20. Stage 5 — Graph Construction

After the transformer has produced edge probabilities, the candidate relationships are converted into graph edges.

See [Graph Construction](../graph-construction/knowledge.md) for the detailed edge filtering, graph constraints, and ILP explanation.

A candidate edge contains conceptually:

```text
source
target
edge_prob
edge_dist
```

The probability represents:

```text
How strongly does the model believe
these two cells are temporally related?
```

The distance represents:

```text
How far apart are these cells?
```

These are separate properties of the relationship.

---

# 21. Edge Filtering

The default edge threshold is:

```python
threshold = 0.5
```

Candidate edges below this probability are discarded.

The remaining edges are sorted by probability.

When ILP is disabled, the pipeline applies local graph constraints.

The default limits are:

```python
max_parents_per_node = 1
max_children_per_node = 2
```

This reflects a common cell-tracking assumption:

```text
one cell
   │
   └── normally one parent
```

and:

```text
one cell
   │
   ├── child 1
   │
   └── child 2
```

for division.

# 22. Example Tracking Graph

A simple continuation looks like:

```text

   A ────────── B ────────── D
```

A division can look like:

```text

      A
     / \
    B   C
```

The resulting graph therefore encodes temporal relationships rather than merely cell locations.

The graph contains:

### Nodes

```text

```

### Edges

```text

```

# 23. Greedy Graph Construction

Without ILP, edge selection is local.

Conceptually:

```text
sort candidate edges
by probability
      │
      ▼
highest-probability edge
      │
      ▼
does it violate constraints?
      │
   ┌──┴──┐
   │     │
  no    yes
   │     │
   ▼     ▼
accept  reject
```

This process continues until the candidate edges have been considered.

The advantage is that this approach is simple and fast.

The limitation is that each decision is made locally.

A locally attractive edge can sometimes prevent a better overall configuration.

---

# 24. Optional ILP Optimization

The pipeline can optionally perform graph-level optimization with:

```bash
--use-ilp
```

The graph is passed to:

```python
td.solvers.ILPSolver(...)
```

The ILP stage considers the graph globally.

It can incorporate costs associated with:

```text
edge selection
track appearance
track disappearance
division
```

The conceptual difference is:

```text
Greedy:

edge A looks good → accept
edge B looks good → accept
edge C conflicts  → reject
```

versus:

```text
ILP:

consider many candidate relationships
            │
            ▼
      optimize jointly
            │
            ▼
 globally consistent graph
```

Therefore ILP is not another neural-network stage.

It is **graph-level post-processing**.

# 31. The Three Representation Levels

The easiest way to understand the complete system is to view it as three increasingly structured representations.

## Level 1 — Image

The pipeline starts with continuous microscopy data:

```text
3D microscopy intensities
```

The Temporal U-Net operates at this level.

```text
IMAGE
  │
  │ Temporal U-Net
  ▼
DENSE FEATURES + DETECTION FIELD
```

---

## Level 2 — Nodes

The dense detection field is converted into discrete cell centers:

```text
(t,z,y,x)
```

At every detected cell, the pipeline constructs:

```text
U-Net feature
    │
    └── learned image/context representation
```

and:

```text
(t,z,y,x)
    │
    ▼
normalized coordinates
    │
    ▼
sinusoidal encoding
    │
    ▼
32-D positional representation
```

These are concatenated:

```text
32-D U-Net feature
        +
32-D positional feature
        │
        ▼
64-D node
```

Thus:

```text
CELL NODE
   │
   ├── appearance/context
   │       └── 32-D learned feature
   │
   └── position
           └── 32-D deterministic encoding
               of (t,z,y,x)
```

---

## Level 3 — Graph

The transformer compares node representations across consecutive frames.

```text
64-D node A
     │
     ├──────────────┐
     │              │
     ▼              │
64-D node B         │
     │              │
     └──────┬───────┘
            ▼
      Transformer
            │
            ▼
     compatibility score
            │
            ▼
        probability
            │
            ▼
       edge filtering
            │
            ▼
      tracking graph
```

The pipeline therefore transforms:

```text
IMAGE
  │
  ▼
DENSE REPRESENTATION
  │
  ▼
CELL NODES
  │
  ▼
NODE FEATURES
  │
  ▼
TEMPORAL RELATIONSHIPS
  │
  ▼
TRACKING GRAPH
```

# 32. The Most Important Mental Model

The entire architecture can be reduced to three questions.

### Question 1 — Where are the cells?

Answered by the Temporal U-Net:

```text
image
  │
  ▼
detection field
  │
  ▼
cell coordinates
```

### Question 2 — What is each detected cell like?

Answered primarily by the sampled U-Net feature:

```text
cell location
    │
    ▼
U-Net feature
    │
    ▼
appearance/context representation
```

### Question 3 — Which cells belong together through time?

Answered by the node transformer:

```text
source node
+
target node
+
position information
    │
    ▼
transformer
    │
    ▼
temporal compatibility
```

These decisions are then converted into a graph.

# 33. One-Line Summary of Every Stage

The pipeline can be summarized as:

```text
Zarr
 │
 └── raw microscopy data

Preprocessing
 │
 └── normalize + downsample

Temporal U-Net
 │
 ├── dense image features
 └── detection logits

Detection
 │
 └── logits → cell coordinates

Node construction
 │
 ├── U-Net feature
 └── positional encoding
       │
       └── 64-D node

Simple Node Transformer
 │
 └── node pairs → edge scores

Graph construction
 │
 ├── probabilities
 ├── thresholds
 ├── parent/child constraints
 └── distances

Optional ILP
 │
 └── global graph optimization

Output
 │
 └── .geff tracking graph
```

The core conceptual transformation is:

```text
IMAGE
  │
  │ Temporal U-Net
  ▼
DENSE FEATURES + DETECTION FIELD
  │
  │ local maxima
  ▼
CELL COORDINATES
(t,z,y,x)
  │
  ├───────────────────────────────┐
  │                               │
  ▼                               ▼
U-Net feature                 positional encoding
32-D learned                  32-D deterministic
  │                               │
  └──────────────┬────────────────┘

                 ▼

                 │

```

The key principle is:

> **The U-Net tells the transformer what the cell looks like, the positional encoding tells it where the cell is, and the transformer uses both to determine which cells are temporally related.**

# 34. Debugging the Pipeline

The separation into stages makes debugging considerably easier.

## Problem: Too few detected cells

Inspect:

```text
image normalization
       │
       ▼
downsampling
       │
       ▼
Temporal U-Net
       │
       ▼
detection threshold
       │
       ▼
local-max suppression
```

A particularly important metric is **node recall**.

Low node recall indicates that the problem occurs before or during detection.

---

## Problem: Cells are detected but links are wrong

Inspect:

```text
U-Net node features
       │
       ▼
positional encoding
       │
       ▼
Simple Node Transformer
       │
       ▼
edge probabilities
       │
       ▼
edge threshold
```

The detector may be working correctly while the temporal association model is failing.

---

## Problem: Edge predictions look reasonable but tracks are inconsistent

Inspect:

```text
edge filtering
       │
       ▼
parent/child constraints
       │
       ▼
greedy selection
       │
       ▼
optional ILP
```

This points toward graph-level processing rather than image detection.

# 35. Evaluation

The generated graph can be evaluated using the repository's tracking metrics.

Important metrics include:

```text
score
edge_jaccard
adj_edge_jaccard
division_jaccard
node_recall
```

These metrics help distinguish detection errors from tracking errors.

For example:

```text
high node recall
+
low edge Jaccard
```

suggests:

```text
cells are being detected
but temporal associations are poor
```

Whereas:

```text
low node recall
```

indicates a problem much earlier in the pipeline.

This distinction is important because the transformer cannot recover a cell that the detector never produced as a node.

# 37. Final Architecture Summary

The pipeline is best understood as a sequence of transformations:

```text
                    RAW MICROSCOPY
                          │
                          ▼
                 ┌─────────────────┐
                 │ Image           │
                 │ preprocessing   │
                 └────────┬────────┘
                          │
                          ▼
                  MODEL-READY VIDEO
                          │
                          ▼
                 ┌─────────────────┐
                 │ Temporal U-Net  │
                 └────────┬────────┘
                          │
              ┌───────────┴───────────┐
              │                       │
              ▼                       ▼
       DETECTION FIELD          U-NET FEATURES
              │                       │
              ▼                       │
       CELL DETECTIONS                │
              │                       │
              └───────────┬───────────┘
                          ▼
                   NODE FEATURES
                          │
                          ▼
                 ┌─────────────────┐
                 │ Simple Node     │
                 │ Transformer     │
                 └────────┬────────┘
                          │
                          ▼
                   EDGE SCORES
                          │
                          ▼
                EDGE PROBABILITIES
                          │
                          ▼
               GRAPH CONSTRAINTS
                          │
                          ▼
                  TRACKING GRAPH
                          │
                          ▼
                  OPTIONAL ILP
                          │
                          ▼
                       .GEFF
```

The architecture therefore separates three fundamentally different tasks:

```text
1. Detection
   "Where are the cells?"

2. Representation
   "What does each detected cell look like,
    and where is it?"

3. Association
   "Which cells correspond across time?"
```

That separation is the central design principle of the entire pipeline.

It allows each failure mode to be investigated independently and makes the system substantially easier to understand than a model that attempts to directly predict complete tracks from raw microscopy images.

# Quiz: Understanding Tracking Graph Structure and Components
## Question 1
What are the key components of a tracking graph generated by the pipeline?

### Answer: Nodes (t, z, y, x) and edges (source, target, edge probability, spatial distance)

Explanation: The graph contains nodes representing cell locations at specific times, positions, and depths, connected by edges that represent temporal relationships between these nodes.

# Quiz: Neural Network Components
## Question 2
Which part of the pipeline is primarily responsible for learning from raw image data?

### Answer: Temporal U-Net (3D Temporal UNet)

Explanation: The U-Net component learns to extract features and generate dense feature maps from the input images.

# Quiz: Data Preparation
## Question 3
What operation does img_proc.py perform on the input images before processing?

### Answer: Normalization, isotropic resampling, NMS, coordinate transformations

Explanation: The script handles image normalization, converting them to an isotropic format (resampling if necessary), applying non-maximum suppression (NMS) for detecting cells, and translating coordinates into a consistent format.

# Quiz: Model Configuration
## Question 4
What are the spatial downsample settings of the Temporal U-Net model?

### Answer: [1, 4, 4]

Explanation: The Temporal U-Net architecture uses downsampling in each spatial dimension by factors of 1 and 4.

# Quiz: Tracking Graph Output
## Question 5
What file format do prediction outputs use to store the tracking graph?

### Answer: .geff

Explanation: The output file is named .geff, which represents a specialized graph data structure designed for storage and evaluation purposes.

# Quiz: Evaluation Metrics
## Question 6
Which metric evaluates how well nodes are recovered by the system across all frames of the video sequence?

### Answer: Node Recall

Explanation: Node Recall measures the proportion of actual nodes that are correctly identified over the entire video sequence, indicating how many times a node appears in at least one frame.

# Quiz: Neural Network vs. Graph-Level Processing
## Question 7
What distinguishes the ILP (Integer Linear Programming) stage from previous stages?

### Answer: It operates on the graph-level to optimize overall track consistency globally.

Explanation: The ILP stage considers all edges and tracks them together, aiming for a globally consistent set of tracks by incorporating costs related to appearance, disappearance, division, and selection decisions.
